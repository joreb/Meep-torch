# 3D chi2 (second-order nonlinearity) — plan

Status: **proposed, not implemented** (awaiting go)
Date: 2026-08-17
Driver: Phase 3 of the device-suite TFLN SHG ring needs a poled ring in *3D*.
`stepper_3d` and `stepper_3d_lean` have no chi2 at all today; `stepper.py` (2D
TM) does.

## Why this is not a port of the 2D code

The 2D TM stepper can solve chi2 cleanly because it advances **D**, then
recovers E from D pointwise:

```python
# stepper.py, TM: one scalar field, D already known
rhs = Dz - P_new.sum(0)
Ez = rhs / m.eps_inf
if m.has_kerr or m.has_chi2:
    for _ in range(3):                       # fixed point
        Ez = rhs / (m.eps_inf + m.chi2 * Ez + m.chi3 * Ez * Ez)
```

Two properties make that work, and **3D has neither**:

1. **TM is scalar.** Only `Ez` is nonzero, so `D = eps*E + chi2*E^2` is a scalar
   equation per cell. In 3D the constitutive relation couples components —
   chi2 is a rank-3 tensor `d_ijk`, and even the reduced `d_33`-only case makes
   `D_z` depend on `E_z^2` while `D_x`, `D_y` pick up cross terms.
2. **2D stores D.** Both 3D steppers advance **E directly** from the curl
   (`F["Ez"].add_(curl.mul_(c.inv_eps["z"]).mul_(dt))`) and never materialise D.
   There is no `rhs` to iterate against.

So this is a real feature, not a transcription. Anyone estimating it as "copy
the 2D fixed point" will be wrong by a wide margin.

## Scope decision: d_33 only

Full `d_ijk` in 3D means 18 independent coefficients and a coupled 3x3 solve per
cell per step. The device-suite device does not need it: **X-cut / Z-cut TFLN driven
quasi-TE uses the `d_33` component**, i.e. only the field component along the
crystal axis participates. Implement:

```
D_z = eps_zz * E_z + 2 * d_33 * E_z^2
D_x = eps_xx * E_x,      D_y = eps_yy * E_y      (linear)
```

This keeps the per-cell solve **scalar in E_z**, exactly like 2D, and covers the
physics the ring needs. A full-tensor path can come later if a device demands
it; do not build it speculatively.

## Implementation

### 1. Store D_z (general stepper)

The scalar fixed point needs a `rhs`. Options:

- **(a) Materialise D_z.** Add one field, advance `D_z` from the curl, then
  solve for `E_z`. Costs one extra `(nx, ny, nz)` array.
- **(b) Reconstruct rhs in place.** No extra static array — one pooled scratch.

Prefer **(b)**: memory on this box is the binding constraint (a 139M-cell grid
already needs 15.2 GB).

### The rhs must carry the nonlinear part of D_old

**This is the trap, and the first draft of this plan got it wrong.** The
reconstruction is NOT `rhs = eps_zz * E_z_linear`. That expands to
`eps_zz*Ez_old + dt*curl`, which is only the *linear* part of D. The real D
also carries `chi2*Ez_old^2` from the previous step, and the 2D scheme works
precisely because D **accumulates** that nonlinear polarization across steps.
Drop it and the SHG drive partially cancels every step — conversion comes out
wrong, and not subtly.

Correct:

```python
# BEFORE the in-place linear E update, stash the nonlinear part of D_old:
nl_old = chi2 * Ez_old * Ez_old            # into a pooled scratch slot
# ... linear curl update runs, giving Ez_lin ...
rhs = eps_zz * Ez_old + nl_old + dt * curl_z     # == D_new
Ez = Ez_lin
for _ in range(3):
    Ez = rhs / (eps_zz + chi2 * Ez)
```

Verified on a single cell against the true D-advancing scheme: the corrected
form matches to 5.5e-07, while the naive `eps_zz * Ez_lin` version errs **3.44%
per step** — the omitted `chi2*Ez_old^2` was 2.6x larger than the whole
per-step curl drive. Validation #1 (2D-vs-3D uniform-slab parity) would have
caught it, but not before burning an overnight run.

### 2. Fixed point, 3 iterations

```python
if c.has_chi2:
    rhs = c.eps_zz * Ez_lin                      # what the linear step gave
    Ez = Ez_lin
    for _ in range(3):
        Ez = rhs / (c.eps_zz + c.chi2 * Ez)      # chi2 is the SIGNED poled mask
```

3 iterations matches the 2D stepper and converges for the perturbative chi2 the
ring uses. **Gate it on `has_chi2`** so the linear path keeps its current speed
— the 2D nonlinear runs measured a ~2x per-step cost from this iteration, which
is exactly why the b_ring grinds were 30 h and not 14 h.

### 3. 3D poled mask

2D already builds a signed arc-angle mask (`b_ring_shg.poling_mask`): +1/-1
alternating every `Lambda/2` of arc, `Lambda = lam_SH/dn = 3.43 um`, 183
half-domains at r=50. In 3D the poling is **uniform in z through the film** —
periodic poling is a lithographic domain pattern, not a vertical structure. So:

```python
chi2_3d = chi2_2d_mask[:, :, None] * core_z_mask[None, None, :]
```

Reuse the 2D function; do not reimplement the arc geometry.

### 4. Lean-stepper variant

`stepper_3d_lean` is forward-only with in-place updates and a scratch pool. The
fixed point needs one temporary of the `Ez` shape — take it from the existing
pool (`c.buf(shape)`), do not allocate per step. In-place `add_`/`mul_` chains
must not alias the iterate; write the loop with an explicit scratch buffer.

## Validation

1. **Parity vs 2D.** Run the same poled ring cross-section as a 2D TM problem
   and as a 3D problem with a uniform slab; conversion efficiency should agree
   to the discretisation error. This is the only test that catches a wrong
   factor of 2 in `2*d_33*E^2`.
2. **Undepleted P^2 law.** `eta(2A)/eta(A) = 4` within 15%, the same gate the 2D
   ring uses. Buildup-independent (the ratio cancels `B(t)`), so it can run
   short.
3. **Poling sanity.** An UNPOLED 3D ring must convert ~nothing (366 coherence
   lengths at dn=0.1965); a poled one must beat it by orders of magnitude. If
   poled and unpoled agree, the mask sign is not reaching the E-update.
4. **Energy.** SH power must stay far below pump power; if the fixed point
   diverges it shows up as growing total energy.

## Cost

Per-step cost roughly **2x** the linear 3D step (measured in 2D). A 3D poled
ring at the sizes Phase 2 used (139M cells, 15.2 GB pooled lean) is therefore an
overnight run per amplitude, and the P^2 gate needs two. Size it against
**measured** throughput, not array arithmetic — the static count under-predicted
3D peak memory by ~2.5x on this hardware.

## Explicitly out of scope

- Full `d_ijk` tensor chi2.
- chi3 in 3D (the Kerr gate is a 2D ringdown measurement; no 3D need yet).
- Adjoint/gradient support through the nonlinear step — the lean stepper is
  forward-only by design, and nothing in the queue optimises a nonlinear 3D
  device.
